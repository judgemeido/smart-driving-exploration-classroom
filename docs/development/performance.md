# 性能优化记录（2026-11-16）

本次从 GitHub 恢复的版本保持内容不变：历史展项、文字、图片主题、章节和交互均保留。所有原始图片、GLB 和建模源文件均未替换或删除；运行时优先使用轻量派生素材。

## 运行策略

- 博物馆右上角及科学活动观察台提供“自动适配 / 标准版 / 低配版”，偏好保存在本机，并同步到同源雷达展厅和探索课堂；自动选项显示实际采用的版本。
- 自动模式在逻辑核心数 ≤4、报告内存 ≤4 GB、省流量模式或小屏触控设备时使用流畅档。标准档连续渲染耗时偏高也会自动切换。
- 流畅档上限 30 FPS、DPR 1、单画布 60 万像素（第三轮从 85 万收紧）；关闭实时阴影和雷达多次离屏泛光，保留扫描、光束、投影环及零件交互。
- 标准版上限 60 FPS、DPR 1.5、单画布 200 万像素。实际帧率取决于硬件和场景。
- 章节隐藏、浏览器切后台时停止渲染；雷达两个画布离开可视区域时也停止。返回保留操作状态。
- 历史页继续按需加载，不预载 Three.js 或 3D 模型。照片使用懒加载、异步解码及 480/960 宽 WebP，原图兜底。
- 车辆开门、后备箱和爆炸图动画收敛后不重复写入变换。道路问答的车辆作为整体合并绘制，第二章可拆解车辆保持独立节点。

## 验证与边界

单元测试、浏览器交互检查和构建通过，涵盖博物馆导航、车辆交互、雷达扫描、手机导航、探索课堂和道路问答。性能用例还检查压缩素材下载失败时回退原模型、隐藏章节停止渲染，以及手机画质控件不被遮挡。

`browser-audit.json` 记录桌面 1920×1080 / DPR 2 与手机 390×844 / DPR 3 的画布预算和帧数。审计使用 CPU 4 倍降速，向网页报告 2 核 / 2 GB；实际 GPU 型号在报告中列出，未模拟低端显卡，因此该结果不能当作真实旧手机的帧率保证。隐藏雷达的实测渲染帧增量为 0。

渲染耗时采样衡量 CPU 提交时间，配合持续帧间隔检测自动降档，仍不能精确衡量 GPU 成本；可手动选择“低配版”。抗锯齿和 GPU 电源偏好在创建画布时确定，切换版本会即时调整分辨率、阴影和后处理，不会销毁正在操作的场景。

## 第二轮：减少持续计算和临时分配

- 暂停雷达、爆炸图动画结束后，只有相机、测距、选中零件等状态变化时才重绘；拖动阻尼和单次光脉冲继续完整播放。车辆相机和机构静止时也跳过重复绘制，保留原有自动转动。
- 16 通道扫描共用一次场景矩阵更新及可见目标列表，原来每个通道各更新一次。公开的单通道测距仍独立刷新，移动墙面后结果及时更新。
- 点云缓冲只上传新点覆盖的范围，点云环形覆盖时正确合并范围；离屏时不会积累无限上传任务。浏览器用例验证单次扫描更新的上传块小于 2 KB，而原实现每个颜色/位置缓冲为 192 KB。
- 缓存刚性零件的局部矩阵、雷达旋转节点和零件列表，保留门、尾门、爆炸图及扫描部件的活动变换。
- 车辆聚焦按原始材质和相同显示状态共享临时材质。开发审计实测电池 29、座舱 39、智驾 36 份，恢复整车时全部释放；10 轮点选/关闭弹窗创建 10 份、释放 10 份高亮材质。审计记录见 `material-audit.json`，可用 `node authoring/performance-tools/audit-materials.mjs` 复现。
- 本轮 300 项单元测试通过；新增浏览器检查覆盖暂停后唤醒、镜头拖动、近物遮挡、16 通道测距和局部点云上传。内容和原始素材未改动。

## 第三轮：面向 i3-1115G4 的绘制提交优化

- 自动模式在报告四个逻辑线程时仍选择流畅档，即使报告内存为 16 GB；无需依赖处理器型号字符串，也不需要额外授权读取设备信息。保持 30 FPS 上限，将像素预算收紧到 60 万，较上一轮减少约 29%。
- `src/shared/rigid-batches.ts` 为同一机构下、相同不透明材质、固定局部矩阵的叶零件建立绘制代理。只在真正绘制时挂入代理并临时隐藏其原网格，绘制后恢复，包括发生异常的情况。原始模型、命名节点、点击射线和拆解分类保持独立。
- 代理与原零件共享运动父节点，车门、尾门和爆炸图保持运动一致。零件被单独隐藏、高亮、修改局部变换，或使用透明材质时，相关批次自动使用原始零件绘制。量化位置/法线先转浮点再烘焙，避免合并后坐标被截断；负尺度、骨骼和形变零件保守跳过。
- 聚焦时的不透明主体继续使用不透明通道，周围的透明展示保留。透明玻璃及外壳不参与合并，确保遮挡和观察内部的效果。
- 四逻辑线程 / 8 GB 提示、CPU 4 倍降速的开发审计中，整车实际绘制调用从 797 降到 249（约 69%），三角形数均为 374,025；电池 1367 → 1320、座舱 1290 → 1178、智驾 1153 → 1146。后三项仍保留透明背景，因此优化幅度较小。画布实测 599,536 像素，爆炸后的电驱零件仍能点选弹窗。
- 同一镜头、同一像素尺寸的合并前后截图对比，约 60 万像素中的显著差异少于 0.01%，平均通道差异小于 0.01/255（具体值随镜头转动而变化，见图片对比记录）。未减少模型三角面或图片内容。
- 点选时先通过可见节点收集目标，再进行三角形求交；修复过滤后仍可能点中隐藏外壳的问题，也避免对隐藏机构逐一计算点击交点。开发审计核对弹窗所属系统必须为当前筛选的电驱系统。
- 开发审计仍使用 RTX 4060 GPU，四线程和内存为浏览器提示、CPU 为节流条件，不能作为 i3 核显实测帧率。完整数据和复现脚本见 `authoring/performance-tools/i3-audit.json`、`i3-image-diff.json`、`audit-i3.mjs`。在开发服务运行时执行 `node authoring/performance-tools/audit-i3.mjs`。

## 标准版 / 低配版自动适配

- 默认“自动适配”：四线程及以下、报告内存 4 GB 及以下、小屏触控或省流量设备优先低配版；其他设备先使用标准版。浏览器无法可靠提供完整硬件规格，因此同时检测实际运行状况。
- 保留原有持续 CPU 提交耗时降档条件。新增持续帧间隔检测：跳过前 30 帧，随后 90 帧中至少 54 帧的间隔超过 38 ms 时转为低配版；超过 250 ms 的中断清空此窗口，避免把离开页面或长暂停当成稳定负载。
- 自动降档结果使用会话存储，在同一标签页的主展馆和雷达 iframe 间同步，并在刷新及进入其他活动时沿用。自动模式本次会话不反复升降，重新选择自动适配会清除运行检测结果并重新评估；手动指定标准版或低配版时不自动覆盖。
- 手动选择保存在本地。选择后移除预览 URL 的 `quality` 参数，保留章节和其他参数，避免旧的强制低配链接在刷新后覆盖新选择。底层 `high` / `low` 值保持兼容已有链接。
- 新用例覆盖不同硬件提示、健康/缓慢帧序列、暂停、显式标准版、URL 与刷新记忆、iframe 同步、手机科学活动切换；不修改教学内容。
