# 电池发展与整车演进实施计划

**Goal:** 在最前面加入 00 电池发展，并让 01 用可辨识的完整汽车展示技术变化，与 02 部件拆解区分。

**Architecture:** 沿用 TypeScript / Three.js 的课堂、工作台、证据和本地存储。新增 battery 与 evolution 两类场景；每个场景的模型、说明和记录来自相同快照。保留旧 URL 和旧学习记录。

**依据:** 用户本轮明确要求实施，前文已确认教师讲解后每人独立操作、点击选择、桌面任务一页容纳。继续使用当前浅色展册界面。

## 分工与接口

- 电池 agent：`activities/battery.ts`、`battery-state.ts`、`mechanical-battery.ts`、`battery.css`；导出 `createBatteryExperiment` 和 `createBatteryRig`，活动 ID 为 B1，章节 battery。
- 整车 agent：`activities/evolution.ts`、`evolution-state.ts`、`mechanical-evolution.ts`、`evolution.css`，调整 `activities/history.ts`；导出 `createEvolutionRig`，H1/H2 使用 evolution 场景。
- 主 agent：类型、导航、工作台集成、舞台、存储、响应布局与现有测试更新。
- 验收 agent：新活动回归测试、科学来源和教师说明。

## 全局要求

- 顺序为 00 电池、01 汽车演进、02 系统拆解、03 感知、04 道路安全；原版展馆保留。
- 00 提供铅酸、镍氢、磷酸铁锂、三元锂；区分历史发展和当下并行选择。以可见结构、充放电方向和定性取舍为核心，不虚构续航或性能排名。
- 01 第一屏显示完整整车；四个年代有独立形体，点击选择能切换车辆与能源说明。H2 的电源/传动断开教学行为保留，燃油与混动仅说明已建模的范围。
- 保留点击预测、操作、证据、发现；没有打字、游戏积分或倒计时。
- 无 WebGL、减少动画、键盘操作、刷新恢复仍可完成任务。

1. 新电池记录刷新后仍可读取，旧证据保持原样。
2. 切换不同车与电池后，当前选中部件确实存在，说明与图形相符。
3. 完整车型轮廓在默认视图清楚，切开和分解后可恢复。
4. 低性能或图形不可用时仍能选择并保存证据。
5. 小桌面顶部五个章节不溢出，主要任务与操作按钮可达。
