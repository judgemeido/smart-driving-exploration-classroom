# 智能驾驶科普公开课 · 2D 改版设计稿 V1

日期：2026-11-08。状态：供审阅的改版建议，尚未实施或经过儿童试玩。

## 1. 已确认的课堂条件

- 150 分钟，36 名三至六年级学生，新手，每人一台电脑。
- 全程数字活动，没有可用的实体部件；删除实体制造、实体装配环节。
- 开放式项目，允许不同方案和改进路径。
- 科普类别下需要丰富、有趣的互动和知识交流，外观与组织方式应呈现为科普学习活动。
- 使用 2D 平面 UI 即可完成。

下列安排是本版建议，不视为用户已逐项确认：独立课堂入口、十个短活动、两次课堂竞答、一个综合实验、具体页面与技术合同。

## 2. 定位与学习成果

名称建议：**智驾探索课堂**；沿用项目“智驾博物馆”品牌关联。

课堂主问题：**怎样让一辆小车安全通过学校门口？**

核心体验：观察 → 操作 → 预测 → 验证 → 解释 → 改进。每个互动都有可观察对象、实质操作、原因反馈和简短记录。仅更换选择题标题不算完成改版。

学生课后应能：

1. 说明感知设备、计算系统和执行部件如何配合。
2. 区分图像信息、距离信息及信息不可靠的情况。
3. 根据道路条件解释一种合适的行动。
4. 用两次测试记录说明自己的修改和结果变化。

开放性保留在设备组合、实验比较、规则调整和解释中。基础事实、交通规则与场景给定条件有明确反馈；开放理由不按关键词自动评分。

## 3. 呈现边界

前台使用“探索活动、观察、预测、验证、实验记录、课堂竞答、方案改进”等名称。操作乐趣来自寻找、连接、测量、选择后果和修复。

不设金币、生命值、虚拟商城、淘汰、连续登录奖励或强制关卡解锁。完成用勾选和记录表达，不包装成角色等级。默认活动不限时；教师管理课堂节奏，不给每个学生设置倒计时。

课堂竞答保留两次，各 5 分钟并包含在章节时间内。每次 3 题、每题 1 分；所有学生先独立提交，再统一讲解，不奖励作答速度，不建立跨年级排行榜。提交冻结首答，仅显示已提交；教师口头宣布后，学生自行点击“进入复习”才揭示分数、答案与解释，无联网锁定或防提前查看承诺。昵称/座位号可选，第一版不收集姓名。没有联网服务时，成绩只在本机呈现，教师用投屏、举手和口头交流组织比较，不显示伪造的班级统计。

## 5. 四个学习区的行为

- **H1/H2：**从已有中国新能源发展资料选取三个事件，保留原年份及出处；不要将其冒充完整世界汽车史。需求匹配允许技术发展并存，不暗示电动化结束后才出现智能化。
- **E1：**平面车图标出感知设备、计算系统、驱动电机、制动/转向四类功能区域，图中标明“功能示意”。计算系统与信号路径可用示意符号，不伪称真实车型位置。
- **E2：**连接“设备信息 → 计算判断 → 执行动作”，连通后播放一次信息流。电池至电机的能量链为选做，避免与信息流混为一条线。
- **S1：**同一场景切换摄像头图像、毫米波雷达距离/相对速度信息、激光雷达距离/空间点示意。语义识别由配套算法解释，传感器自身不直接产生完整驾驶决策。
- **S2：**先判断最近目标、选择区间，再揭示距离；使用现有三轮米制数据。图形、标尺与判定用同一数据，缩放不改答案；精确距离在提交前隐藏。
- **S3：**固定目标和设备，仅切换正常、雨、雾进行定性对比；不编造实际识别率。学生记录一个变化及一种降低风险的行动。
- **T1/T2：**每个场景先找实际线索再选动作；反馈说明结果与原因，不在作答前高亮答案。红灯、行人、不可靠信息为基础覆盖，其他交通情况选做。
- **T3：**给出“发现行人但未设置对应规则”的记录，学生修改规则再运行。复用综合实验的判断引擎，避免诊断页和最终实验使用两套结论。

错误后保留正确部分；提示指出下一步操作。三四年级默认“引导模式”，五六年级可用“自主模式”，也可自行切换；两种模式的科学事实和安全判定一致，只调整干扰项、提示及开放表达量。

## 6. 综合实验与教学模型

统一使用校园小车，第一版提供摄像头、毫米波雷达、激光雷达，固定谨慎运行，不提供缺乏动力学支撑的速度调节。基础路径不限制预算；进阶可选 80 点预算，设备成本 20/30/50 点，仅为教学参数。超预算阻止开始并解释，不能运行后才扣分。

规则条件：行人过街、红灯、信息不可靠、确认可通行。动作：停车等待、降低风险并安全停车提示、谨慎前进。提供推荐模板，允许删除、更换和比较；优先级按“信息不可靠 → 行人 → 红灯 → 已确认可通行”固定，界面可见。多个匹配规则同条件动作冲突时阻止运行，要求学生解决。缺失安全规则会产生可诊断的风险记录；未知信息不能自动当作空路。

这是离散事件的教学模型，不做真实车辆动力学、真实感知算法或制动距离计算。道路图、车辆动作和报告都从同一事件记录生成；重播不重新计算；结论不能推广为真实车辆安全认证。

| 场景 ID | 给定条件与信息 | 应体现的结果 |
| --- | --- | --- |
| school-crossing | 晴天、具备停车条件；行人进入再离开斑马线；设备可提供目标证据 | 行人阶段停车；确认清空后继续；始终停车显示安全处理但任务未完成 |
| signal-change | 红灯后转绿且通行区域已确认无冲突；灯色证据需摄像头及配套识别示意 | 红灯停，确认可行后继续；只有距离设备不能凭空获得灯色；缺少证据进入不可靠状态 |
| rain-uncertain | 雨天，场景明确给定前方证据持续不可靠，且预留安全停靠条件 | 降低风险并安全停车提示可计为本场景任务完成；增装设备不自动解除本次不可靠状态 |

三个场景初始条件固定、不随机，同输入产生同输出。推荐初始配置：摄像头＋毫米波雷达、行人停车/红灯停车/确认通行三条规则，故意缺少不可靠信息规则，供首测诊断。页面说明“这是待完善的示例方案”。补充对应安全动作后可复测改善。

引擎按下列事件合同执行，不让实施者猜测车辆默认动作：

- 晴天有摄像头及配套识别示意时，school-crossing 依次产生 pedestrian、clear，signal-change 依次产生 red-light、clear；毫米波/激光雷达可补充距离等证据，但不凭空识别灯色。缺少摄像头时，这两个基础场景以 uncertain 处理目标类别或信号未可靠确认，安全停车可认可安全处理但未完成通行。camera 单独可在这两个固定教学场景提供足够证据，不强制增加设备。
- rain-uncertain 始终产生 uncertain，不因装备增加而变成 clear。设备信息视图保留三类信息的差异。
- pedestrian/red-light 下 wait 安全，随后消费场景的 clear 事件；cautious-go 未通过安全处理验证；safe-stop-alert 安全但提前终止通行，任务未完成。
- clear 下 cautious-go 安全且完成通行；wait/safe-stop-alert 安全但未完成。uncertain 下 safe-stop-alert 安全；在雨天给定停靠任务中也算完成；wait 安全但缺少本场景要求的提示，任务未完成；cautious-go 未通过安全处理验证。
- 无规则匹配记 action=null，画面暂停，反馈“缺少必要策略，无法确认安全处理”；行人/红灯/不可靠条件下 safe=false，clear 下 safe=true 且 taskCompleted=false。不编造缺规则后自动加速或撞人的默认行为；safe 字段代表本模型的安全处理验证结论。出现验证失败或 safe-stop-alert 后结束本场景；同条件重复同动作按一条处理。

结果分别显示“安全处理”和“任务完成”，均使用是/否及原因，不合成不可解释总分。每轮包含三个场景；最少保存两轮，报告标出改变的配置字段及结果变化。没有变化的复测仍真实保存并提示，没有虚构进步。

## 7. 页面、课堂组织与保存

新增独立入口 `classroom/index.html`，内含首页、history/explore/lidar/traffic 四个学习区、workbench 综合实验和report 成果页。全程 2D，不加载 Three.js/GLB/DAE，不复用旧三维控制器。

本版建议保留现有主站作资料入口；课堂入口作为新增路径，实施时只增加清晰的入口链接。现存其他独立活动方案与本版为待选路线，不能把计分、计时和导航要求混合执行。

工作区：顶部一句目标与步骤；左侧约 2/3 图形操作区，右侧约 1/3 短提示/证据；底部一个主要操作。综合实验右侧配置只含设备和规则。先按教室桌面 1366×768 与 1280×720 验证；正文/按钮至少 18px、辅助字至少 16px、交互目标至少 44×44 CSS px。200% 缩放允许重排与滚动，主要按钮可达。拖放必须有点击与键盘等效操作，颜色之外有符号与文字，动画可暂停、重播、跳过，减少动态效果保留同样结论。

36 人组成 18 对同伴，每人独立作品；不开发实时多人协作。教师阶段导航显示剩余建议时长、讲解问题及活动直达链接，无远程锁屏、远程控机、全班实时进度或虚拟排行榜。

本地自动保存学习记录、草稿与测试轮次，刷新恢复；失败时明确“尚未保存”。本机报告支持打印/PDF与 JSON 导出导入：前者便于现场查看和集中收集，后者便于换机恢复。第一版不做网络上传，提交方式是保存文件到教师指定的共享文件夹或学校现有平台，课堂前由教师落实该渠道；无渠道则现场检查本机报告，不假称已提交。不同电脑、浏览器、域名、端口的本地记录不互通。

## 8. 验收与实施边界

第一批先验证 E2 信息链、T3 诊断及一次修改复测；第二批补齐十个短活动和两次竞答；第三批完成报告、保存与教室部署。

功能验收包括：无 3D 运行依赖；错误可修复；操作和答案同源；刷新恢复；相同输入结果一致；设备与规则确实影响结果；安全和任务完成分开；旧主站可用；子路径部署可直接访问；存储失败可继续且有导出。

课堂验收先邀请至少 6 名儿童、覆盖三四和五六年级。观察 5/6 能否在一次共同示范后独立完成“操作—验证—修正”，至少 4/6 能否借助记录说出一次修改原因；记录实际耗时与求助点，未达到则简化操作或提示再试。该人数和阈值是本版试讲建议，不是已获得的证据。

不纳入本期：实体课程、完整 3D 改造、真实自动驾驶算法、账号与后端、班级联网竞赛、在线 AI 助教、商业游戏经济系统。预估排期须先测一个完整样例的实现和试讲耗时，再承诺交付日期。
