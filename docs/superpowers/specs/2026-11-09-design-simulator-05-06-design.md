## 1. 要补什么，为什么补

05负责“提出方案”，06负责“用证据检验方案”。两页接续01–04，组成：认识知识 → 配置方案 → 预测 → 测试 → 找到问题 → 只改一项 → 同条件复测 → 解释。

已确认：三至六年级、每人一台电脑、教师先讲后独立操作、纯网页、无实体。总课时、班级人数、教室硬件未确认。本稿建议05基础约8–12分钟、06约12–18分钟，只作备课参考。

## 2. 页面与学生操作

### 05：汽车设计工坊——给校园教学车制定处理方案

首屏明确“本次任务：让教学车在校门附近依据可靠证据行动”。中心是可旋转、开壳和分层的功能车；右侧为当前一步的短工具；底部显示方案摘要与下一步。左侧四步导航随时可返回，不设倒计时与通关锁。

| 步骤 | 学生具体做什么 | 立即看到什么 | 留下什么 |
|---|---|---|---|
| 读任务、选起点 | 读校门任务与成功条件，选择推荐起步方案或空白方案 | 三个待验证情境、方案尚未验证的提示 | 个人方案名，可选，不要求姓名 |
| 配置信息来源 | 选择摄像头/毫米波雷达/激光雷达，再点击对应安装位；键盘列表等效 | 设备出现在车上；切换“设备提供的证据”说明与局限；覆盖区域明确是示意，不冒充真实量程 | 设备集合，以及一条“我为什么需要这类信息”短句 |
| 接通与制定规则 | 点击端口或使用连接列表接通“感知→计算→执行”；为四类条件选动作 | 信息路径、断口和规则句“如果……就……”同步变化；重复条件直接定位冲突行 | 连接与规则，允许保留有意义的缺项供测试诊断 |
| 检查并保存版本 | 阅读缺少证据/规则的提醒，写一句预期，保存V1 | 不可变方案卡：版本、设备、规则、连接、预期；标“待验证” | 可以由06准确引用的提交版本 |

主规则条件为“通行区域被占用（有人/障碍）”“红灯”“必要证据不明确”“已确认允许通行且区域清空”；动作是“等待”“停车并提示”“谨慎通行”。不要求拖拽编程，不让孩子输入代码。语法/重复条件是阻断错误；缺设备、缺部分规则或断连接是显式警告，可保存后观察其后果；至少一条合法规则才可保存。

提供“守候方案”起点：摄像头、两段连接完整；占用/红灯/清空均等待，不确定时停车并提示。它能保守处理却不能完成A/B通行，学生可只修改“清空后等待→谨慎通行”，得到明确可解释的改进。提供起点不等于自动完成实验，也不预先标注该配置通过哪些场景。

原四车型（城市SUV、未来轿车、智能校车、无人配送车）与三能源（纯电、混动、氢燃料电池）放入“拓展：表达我的设计”折叠区，默认校园纯电教学车；第一版只记录用途/能源并显示原理说明，明确**不改变道路判定、没有续航/性能排名**。不为四类车型制作四套CAD；采用同一教学模型的用途标签。首版不恢复100点预算：原六设备总价恰好100，没有真实取舍，且费用不是市场价格。后续确有教学需求时另做资源约束实验。

### 06：道路验证实验室——同样条件，方案会怎样处理

首屏顶部固定显示“正在测试：方案名 / Vn”，左侧选场景，中部为三维学校道路沙盘，右侧是三个可展开的证据栏“设备给了什么→规则决定什么→实际执行什么”。当前场景的任务条件始终可读。

| 环节 | 学生具体操作 | 必须出现的反馈 |
|---|---|---|
| 预测 | 选一个已保存版本和场景，写一句预期 | 明确本次会测试哪个版本；没有方案时可载入推荐样例，标“示例方案” |
| 分步验证 | 点击“运行本次验证”，再逐步/播放已生成事件序列 | 占用/灯色/可用与未知证据、命中规则、命令和执行一一对应；可暂停、回看、重播 |
| 定位问题 | 点击“为什么没有完成”，选择输入/规则/连接中的一处 | 指向第一处缺口，显示所依据事件；不先替学生把方案改好 |
| 返回05修改 | 点击“复制本版本去修改”，只改一个条件并保存新版本 | 保留旧版本、旧测试和原预测；新版与旧版的实际配置差异可见 |
| 同条件复测 | 返回06沿用原场景与版本化事件集 | 保持场景、事件、种子、模型、评价版本相同；同方案必须得到同样结果 |
| 比较与解释 | 并排选两次测试，读变化项和逐事件差异，补一句解释 | 分开显示“安全处理是否已验证”“本场景任务是否完成”；一键加入学习记录 |

重播/拖动进度只看既有记录，不重新仿真、不增加实验次数。页面隐藏停止播放，返回不补跑后台时间。没有未知条件下的默认加速，没有撞人演出、竞速、金币或淘汰。缺规则或执行时，教学播放可以停在该事件并标“动作未定义/执行未确认”，不能把暂停画面解释成车辆完成了安全停车。

## 3. 三个基础场景及一个迁移例

首版采用**离散证据事件**，不恢复旧计划0.05秒刚体/制动模型，不显示未经来源支持的真实车速、制动距离或事故概率。画面位移是“到达观察点—等待点—通行/停靠”的教学分段慢放，不参与安全结论计算。

| 场景 | 提供的事件 | 学生需要发现 | 任务完成含义 |
|---|---|---|---|
| A 校门礼让 | 可靠证据表明区域有人/障碍→确认区域清空；无交通灯 | 先停止/等待，再在清空证据成立后通行 | 安全处理成立，并完成条件通行 |
| B 红灯转绿 | 红灯→绿灯但区域仍被占用→绿灯且区域已确认清空 | 绿灯不能覆盖仍有占用；距离设备不直接读灯色 | 两个停止事件均处理正确，最后通行 |
| C 看不清时怎么办 | 关键证据持续不可靠；题设给定可安全停靠条件 | 未知不能当无人；增加设备不能被宣传为一定消除不确定 | 执行停车并提示，完成本场景停靠任务 |
| 迁移：轻雨仍有证据 | 与A相同的事件，天气改为轻雨但题设观测仍可用 | 不能死记“雨天=失效/停车” | 依据实际证据解释与处理；不和晴天记录直接作公平A/B对照 |

首版设备仅三类信息来源。摄像头在清晰样例提供灯色/图像经教学模块解释的占用证据；雷达/激光提供距离和空间占用的教学推导，不直接提供灯色，也不声称直接识别“人”。不实现真实CV、雷达识别或气象衰减。场景数据同时保存世界真值和独立观测，决策只读取观测。每个字段标`available/weakened/unknown`，只有available可满足通行必要条件。

判定优先级：已知占用 > 已知红灯 > 缺少必要证据 > clear。clear在有信号场景必须同时满足可靠的通行信号和清空证据；无信号只要求清空。已知停止原因不会被其他未知信息覆盖。缺规则→命令null；断输入→观测未知，计算仍可按“不确定”规则给出停车命令；断执行→执行null。安全结论不等于动作名称；null、unknown下通行和已知停止原因下通行均不能证明安全处理成立。

动作与任务评价表固定为：

- 占用/红灯：等待或停车并提示可验证当前停止处理，谨慎通行不成立。
- 不确定：等待或停车并提示可验证当前保守处理，谨慎通行不成立。
- clear：三种动作均可安全处理，但A/B必须谨慎通行才算完成通行任务；始终等待仍未完成。
- C：所有事件安全处理成立且最后执行“停车并提示”才完成停靠任务；只有等待缺少提示，不算完成。

“安全处理已验证”严格指本教学事件集，页面不得写成真实自动驾驶安全认证。

## 4. 版本、比较与学习记录

05草稿与已保存版本分离。同一方案版本递增，编辑、另存、改用途不改旧快照。06路由准确引用designId/revision；引用不存在、缺字段、重复字段、非安全整数或非法编码时留在06解释原因，不偷偷换最新版本。

测试保存完整设计快照、场景快照、种子、模型与评价版本、各事件观测/命令/执行、原预测和结果。只能在相同场景快照/种子/模型/评价版本下作受控比较；否则显示“实验条件不同，不能直接归因为方案变化”，仍可分别阅读。

同条件下自动列出设备、连接、规则、用途、能源每一项实际差异。“只改一项”只在确实一项实质配置变化时标注；多项改变如实列出并提示难以单独归因，仍允许探索，不伪造结论。相同配置复测明确“配置未改变”，不制造随机优劣。

当前`#report`保留为学习档案，追加05方案、06测试与配对比较记录、Q1/Q2的首答和修正摘要；不把未进行的记录补成完成。现有7活动、旧成绩不清除。无需账号、小组或实名。新档案采用独立版本化键，不破坏现有两个v1键；存储失败仍保留本次内存并导出，损坏/未来版本只读保护。

实施建议采用单一新键`science-learning:classroom:v2`，内含原活动v1、知识交流v1及设计测试v1。首次没有v2时只读载入现有两个v1；后续写入与整包替换只写一个v2值，旧键原样保留，不做多键“部分导入”。v2损坏/未来版本不得静默退回旧记录后覆盖。现有只含活动的JSON仍可导入，但预览明确“仅替换活动记录，其他类别保留”，不能用空值把设计与测试清掉。

完整课堂文件导出包含原学习活动、知识交流、设计版本、测试和解释。导入先校验、预览记录数与版本，再明确确认替换；不默认合并，失效版本不注入运行器。打印输出以中文条件、证据、结论为主，不把内部JSON和字段名暴露给学生。

## 5. 路由、布局与技术边界

- 顶部导航扩展为01–06；“我的学习记录”仍为独立工具入口。04继续指向当前道路安全页，不在本轮重做。
- `#design`进入05，`#simulator?designId=...&revision=...`进入06准确版本。`#simulator`无引用时列已保存版本/推荐样例；`#workbench`作为06无引用入口的兼容别名，`#report`保持原行为。
- 05四步导航，06场景/证据/对照导航；桌面保留大模型与短工具，只有当前一步展开，避免再次出现整列长表单。当前版本、变量和主操作在1280×720可发现，不依赖长滚动寻找运行按钮。
- 正文/按钮≥18px、辅助≥16px、点击目标≥44px；选择设备、端口连接、规则编辑和播放都有键盘等效。200%和窄屏自然重排，状态同时有文字和线型。
- 沿用TypeScript、Vite、Three.js、原生DOM、Vitest、Playwright。复用现有车辆几何、材质/资源生命周期与同源状态方法；新建道路presenter，禁止用传感台假称完整道路仿真。一视图一renderer；WebGL失败有相同状态驱动的2D/DOM流程。
- 当前E2固定两帧逻辑保留，不直接扩成万能引擎；新增纯事件引擎供05/06。复用科普事实，不能直接用`traceSensor`的单束求交冒充多设备道路识别。舞台仅消费已生成帧，不评分。

## 6. 推荐实施顺序与验收

1. 锁定05配置、版本/路由与06事件合同；先通过纯规则测试。
2. 打通最小闭环：守候V1→A安全但未通行→05只改clear规则保存V2→A同条件复测完成→并排解释。验证真实渲染后才扩展B/C。
3. 完整05四步、三场景、迁移例与道路模型；完善逐步证据、故障定位和比较。
4. 学习档案、Q1/Q2汇总、整包导入导出、打印、键盘/低配/异常恢复与回归。

完成条件：05/06有独立可达页面；保存准确版本；每个配置变化有可追溯证据或明确“不参与判定”；A/B与C的任务完成区别正确；缺设备/规则/连接不默认通过；旧结果不可被草稿改写；不同条件不能假作同条件比较；重播不新增测试；无WebGL仍能完成；原01–04和旧记录可用。

儿童试讲与教室设备性能另作真实验收，自动测试只证明实现规则。多agent实施继续全部使用GPT-6.1 Sol，所有公共入口、构建、端口与Git由单集成人负责。
