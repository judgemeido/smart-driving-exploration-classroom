# 智驾博物馆 · 三维探索课堂设计稿

日期：2026-11-09。状态：供用户审阅，尚未实施；本轮只形成设计与计划。参考当前实现`4f2a829`，不把上轮自动化通过或专家评分当作儿童学习效果证据。

## 1. 课堂条件与设计判断

已确认：每人一台电脑，全程网页交互，没有实体部件；老师先讲解一段，学生再进行对应互动；科普类别下要有丰富的探索、知识交流和学习内容，对外保持科普课程形态；用户要求参考[teardown](https://github.com/elvarofficial/teardown)做三维交互，视觉学习原博物馆界面，先提交plan。

三至六年级是本轮沿用的目标受众。总课时、人数、教室GPU尚未确认；仓库中未提交的旧2D课堂草案写过150分钟/36人，本版不将这些数字当作约束，不覆盖那两份文件。具体活动组合、时长、入口整合方式是以下设计建议。

当前三活动的不足：

- 01有排序、配对和观点拼句，但多数动作改变答案状态，缺少可观察的作用变化；年份能查到也排对了，不代表理解技术因何出现。
- 02主要是把部件放进标有功能的槽，再填关系词；三维车身、真实空间关系、输入与输出的区别没有参与推理。
- 03已有有价值的角度、扫描与米制计算，但接线和天气部分容易变成固定组合答案，完成后锁定，不利于做对照。
- 三页独立开始、计时、计分、结算，与教师讲解和四展厅学习路径割裂。上轮验收主要覆盖可操作、错误恢复和稳定性，没有验证孩子能否解释观察或迁移到新情境。

本版要把成功标准改为：**孩子改变一个条件，看到有因果的变化，用一条证据解释，再换个条件验证。**三维模型是实验对象；旋转、爆炸图和精细外观本身不算完整学习活动。

## 2. 科普形式如何承载参与乐趣

趣味来源是发现、预测揭示、操纵、诊断、修复和比较；学习组织是真实的观察、实验和解释。知识竞答如实叫“课堂知识竞答”，不给刷分玩法换一个实验标题。

| 参与机制 | 页面表达 | 教学证据 |
| --- | --- | --- |
| 寻找、揭开 | 定位部件、打开工作剖面 | 指出部件在哪里、能做什么 |
| 先猜后看 | 记录预测、运行验证 | 预测与实测的差别 |
| 拼接、试错 | 连接信息链、检查断点 | 输入、判断与输出是否连通 |
| 改变量再试 | 同条件对照、复测 | 改了什么、结果如何变化 |
| 找错修复 | 系统诊断、重新验证 | 故障证据与针对性修改 |
| 竞争与交流 | 独立知识竞答、教师讲评 | 首答、解释与讲评后修正 |

前台不用金币、生命值、关卡地图、连胜、等级、商城、淘汰、速度奖励或1000分总榜。平时活动不限时、可反复试；进度显示“已留下哪些观察”，不以全部答对解锁下一章。误判保留并帮助修正，不扣探索资格。

## 3. 一条学习路径，三类共用模型

主问题建议：**小车怎样获得信息、做出判断，并在学校附近采取合适的行动？**

四展厅保留为课程章节：发展脉络 → 结构与系统 → 感知与证据 → 道路判断。十个短活动、两次竞答、一个综合实验是内容库，不要求一节课全部完成。

三类模型共用：

1. **教学车辆与电驱剖面**：已有概念车外形/部件位置，加可见电机、轴、齿轮与车轮连接的功能模型。外形与功能内部明确区分，不能冒充S9官方CAD。
2. **感知设备与测量台**：已有授权雷达外壳，加发射/接收/处理功能剖面、可移动目标、空间遮挡、射线路径与点云。内部标“原理示意”，光脉冲标“慢放示意”。
3. **学校附近道路台**：车辆、信号、行人、遮挡物和观察点。一个固定场景同时服务找线索、信息比较、策略判断、故障诊断和综合复测。

不制作十套互不相干的场景。H1史料、年份、因果说明、竞答和结果对照保持易读的二维DOM；三维用于连接、遮挡、深度、运动、剖切和位置关系。

### 每个课堂段落的节奏

```mermaid
flowchart LR
  A[老师讲一个机制与问题] --> B[学生留下预测]
  B --> C[改变一个条件并运行]
  C --> D[观察模型与同源读数]
  D --> E[保留证据并解释]
  E --> F[换一个条件再验证]
  F --> G[回到老师讲评或下一段]
```

讲解演示由使用者显式打开，可暂停、逐步、重播；学生观察时保持其视角和当前状态。禁用teardown示例25秒无输入自动夺回导览，也不自动跳下一题。老师通过口头或投屏宣布开始操作，学生点击“开始验证”；无联网控班、锁屏或教师实时进度的承诺。

建议每段讲解2–4分钟、学生操作4–7分钟、讲评1–2分钟；这些是可拆用的建议值。首课可选E1/E2/S2/T2加一次短复测，完整内容分多课使用；总时长由实际课表决定。

## 4. 十个活动的具体设计

### H1 汽车进化档案：从证据重建发展片段

- 教师问题：某项需求和技术，为什么会在这些资料里一起出现？
- 学生查看三份真实展品资料的年份/照片/短证据，先预测先后与对应需求，再排列；“查看证据”定位原出处，错误指出冲突证据而非直接自动排序。
- 基础选三事件，扩展选五事件或补充一条并行发展线。取现有中国新能源资料，保留年份和来源，不声称是完整汽车史，不画“前一技术彻底淘汰后一技术”的单线。
- 界面以原馆时间线与档案为主体，允许在相同概念车上查看功能层对照，明确那是原理对照，不能伪造各年代实车。
- 记录：首次排序、引用的一条资料、修正后次序和“这项变化回应了什么需要”。本项是史料推理，不虚称控制变量实验。

### H2 能量怎样到车轮：技术解决什么问题

- 教师先解释能量与运动，学生预测断开供能或传动后哪些部位仍会运动。
- 在固定教学台架上，切换供能通/断或联轴连接通/断，一次只改一处，运行后看到供能指示、电机轴、传动和车轮同步反映状态。
- 断传动时电机可转而车轮不被驱动；断供能时演示驱动停止。台架不模拟车辆惯性、制动距离或真实扭矩；无来源效率不显示精确数。
- 扩展比较电池供电与燃料电池供电后的共同电驱段；混动只列有来源的功能关系，不制作无依据的具体车型机构。
- 记录两次配置、输入/输出变化、解释；迁移题换一个断点。未来设计保留为选做开放讨论，允许自填帮助对象与条件，不设唯一卡组。

### E1 汽车部件观察：找到并打开正在工作的部位

- 先给功能现象，不先把目标名称写在正确位置上；学生在真实三维分组中定位电池、电驱、计算/感知、制动/转向功能区域。
- 点选或键盘列表选择后，镜头聚焦、周围淡出，可控制剖面/分层滑杆；错误选择也显示真实部件作用，允许比较。
- 对所选部位执行一项功能观察：电驱看轴轮转动，感知看信息来源，执行部件看命令状态。空间观察与E2功能验证共用状态，不靠点击次数判完成。
- 识别四类核心功能为基础，13主题为选做资料，不强制逐一完成。
- 记录部位、功能证据和一个仍不确定的问题；不能只凭旋转模型或点亮热点生成完成结论。

### E2 让信息跑起来：连接、运行、定位断点

- 道路中给定一个已知目标，学生预测“看到了”是否自动意味着“停下了”。
- 连接感知输入 → 计算策略 → 执行部件；可点击端口/列表连接，拖线为增强。信息链与供能链分色并有文字，不能混成一条。
- 显式运行后信号逐段传递，打开正在工作的部件；断输入显示“未知”，缺策略显示“没有匹配策略”，执行断开显示“命令未到达”，不是统一红叉。
- 基础修好一处断点；扩展换一条未演示的断点。输入状态、信号光路、动作、事件记录由同一引擎产生。
- 记录首次运行、定位依据、只改的一处和复测差异；随后Q1检查理解，不把背熟连线标签当作实验成功。

### S1 汽车看到了什么：同场景比较三类信息

- 同一学校道路、同一目标，切换摄像头图像、毫米波距离/相对运动、激光空间点；每层只提供它有依据提供的字段。
- 移动目标距离并保持灯色，读数更新；改变灯色保持几何，距离不变。先分别操作，再叠加比较。
- 单纯激光点云/毫米波不声称识别灯色；彩色语义标签与原始测量层明确分开。摄像头图像也不等于一定识别正确。
- 记录“能确认/仍不知道”的字段，迁移到一个遮挡位置；多开设备不自动变成无所不知。

### S2 先猜，再测：一束光的往返

- 首先预测最近目标和距离区间，暂不揭示精确值；再转向、发射、观察反射和接收。
- 可沿标定轴移动一个目标或滑杆控制距离，保持其他量不变；脉冲动画、点云命中、距离、往返时间由同一个米制交点计算。
- 保留`c=299792458m/s`、`t=2d/c`；16m对应约106.7ns，镜头旋转/缩放不改变读数。未命中清空本次读数，不能沿用上一次结果。
- 讲解“除以2”的原因；基础看区间与图示，扩展算式解释。接收部件可剖开看路径，不以反复接错Tx制造主要教学任务。
- 记录预测、两距离/两时间、解释；迁移换视角或目标，验证透视大小不是实际距离。

### S3 天气变化观察：能确定什么，还缺什么

- 固定设备、目标和位置，对比晴天、轻雨、浓雾三个明确标为教学样例的条件；遮挡另做一组，不同时改多个因素后归因。
- 模型显示条件变化，信息面板逐字段标“可确认/变弱/未知”并可查看证据。天气粒子仅表达环境，不能作为设备可靠性的计算证据。
- 轻雨可保留可用距离；浓雾样例可能让图像类别不可靠；毫米波仍有距离信息也不能证实灯色。不公布无来源识别率，不把示例推广成所有设备通用性能。
- 学生选一条未知并说明需要补什么观察，选择安全处理后看依据；没有固定“雨天必须两种特定设备”的唯一配对答案。
- 记录同条件对照和剩余不确定性，迁移到另一目标距离。

### T1 道路线索观察：换位置后，盲区怎样变化

- 先观察一个被停放车辆/遮挡板挡住的过街区域；学生标出已有线索与仍不可确认区域。
- 在封闭教学场景移动观察点或遮挡板，行人与道路保持固定，三维视锥/遮挡区同步变化；这是观察台调整，不教儿童靠冒险驶出遮挡换视野。
- 场景外部全知视角与设备当前可见信息明确区分，不能把全知画面自动送入决策模块。
- 记录前后可见区域与新增证据，解释“未发现”与“没有”的差别；迁移换一处遮挡。

### T2 我来做判断：行动之后，还需要观察什么

- 在明确决策点暂停：例如绿灯但仍有人过街。先预测行动结果，再选等待/谨慎通行/安全停车并提示。
- 执行一步后显示证据 → 判断 → 动作 → 结果，学生控制继续；红灯转绿、行人离开为场景事件，不用倒计时逼反应。
- 允许对同一初态换一策略对照，不用碰撞、生命值或失败淘汰刺激参与。未通过安全处理验证时停在决策点解释，不表演撞人。
- 结果分“安全处理”和“任务完成”：一直等待可能安全但没有完成通行；确认清空且满足信号条件才完成通行。
- 记录行动与理由，迁移到绿灯而行人未清空的不同组合，避免只背交通灯口诀。

### T3 系统诊断：看记录，修复后再运行

- 给出一辆没有按预期处理的教学车；学生打开输入、策略、执行三个工作层，依据同源事件记录找原因。
- 基础一个断点：未接有效证据、缺少策略、执行连接断开三类之一；进阶可换另一类，不默认所有问题都靠加设备。
- 只改一个字段后，从相同场景起点复测，显示哪条记录改变；错误修复保留，提示其没有改变结果的原因。
- 缺策略/缺输入显示未知或缺规则，不凭空默认加速，也不虚构“全车坏了”。
- 记录故障证据、修改、复测结果，直接进入综合实验使用同一工具。

## 5. 知识竞答与综合实验

Q1在E2之后：三题，新现象图检查能量/信息区别、输入输出、断点判断。Q2在T3之后：三题，检查未知、绿灯与行人、停车安全与任务完成。建议各题1分，仅本次答卷诊断，记录首答与讲评后的修正，无速度奖励、跨年级排名或虚构班级统计。题目可为预测/选证据而非全是定义题。

学生独立提交后可先停在“已提交，等老师讲评”；教师口头宣布后学生自行点“查看讲评”。无服务器时它是课堂组织约定，不能声称远程锁定或防提前查看。离开/刷新保存草稿与首答，复习不覆写首答。实验本身无正式局、首局锁或离页作废。

综合实验建议12–18分钟基础，加5–10分钟扩展。主任务是“为学校附近的教学车制定有依据的处理方案”，提供推荐配置可直接进入，无十项全过门禁。

1. 同一配置预测并测试A行人进入后离开、B红灯转绿且区域清空、C给定证据持续不可靠且具备停靠条件三个样例。
2. 看输入/策略/执行记录，选设备信息源、规则或连接其中一类改一处，先写预期。
3. 保持场景/模型版本/初态相同复测，对比两轮。重播不生成新试验；同配置不变如实显示。
4. A/B评价安全且按条件通行；C的任务是安全停车并提示，完成含义按场景区分，不能把所有停车都算满分或都算失败。
5. 再给一个迁移样例，如轻雨但证据可用、绿灯仍有行人、不同遮挡，要求给出证据和剩余未知。

判定约定：每个事件先提供独立观测字段，只有`available`且经过本教学处理模块的字段能满足对应安全条件；`weakened`保留作比较，不能单独证明可通行。已可靠发现行人优先于红灯，红灯优先于缺失的必要信息；有任一已知停止原因，不因为另一个字段未知而丢掉该原因。仅在“信号允许（若本场景有信号）”及“通行区域已确认清空”两项必要证据均有效时为clear；其余为uncertain。场景明示所需证据，不把多个传感器重复计票当可靠性认证。重复同condition的规则冲突阻止运行。

三个基础场景用离散事件而非儿童反应时长：A先可靠看到行人、后确认区域清空（无信号路段）；B先红灯、后绿灯且区域确认清空；C所有事件持续缺少关键证据且存在给定安全停靠条件。A/B在停止条件下wait并在clear下cautious-go可完成；提前stop+alert安全但通行未完成。C的safe-stop-alert完成停靠任务，wait不满足“提示”要求；任何uncertain下cautious-go不通过安全处理验证。展示的是教学规则结论，不模拟真实驾驶系统认证。

不增加真实车速/制动距离/识别准确率/传感器价目表等无来源数值。高年级成本预算可后置，不阻塞第一版。

## 6. 视觉与操作结构

视觉依据是已实际查看的原`#explore/#lidar`：炭黑/深绿界面、米白文字、琥珀强调、青绿信息线、浅绿灰的照明模型台、细线分隔、大模型、右侧说明。引用现有`src/styles/foundation.css`变量：`#0c0d0e/#141617/#f1efe8/#dda35d/#91d8d0`。保留这套身份；不再使用上一轮白蓝操作表单，也不照搬teardown亮色控制台。

同时修正课堂适用性：原界面部分10–13px字和过长侧栏不继承。正文/按钮≥18px、辅助≥16px、目标≥44×44 CSS px；重要操作≥48px，焦点清晰。阅读/操作模式的章标题收敛到28–36px，不让营销式大标题挤走实验对象。

桌面1366×768、1280×720：顶栏含四章节与学习记录；当前目标与阶段在一行；约68%模型台/32%短工具与证据；底部当前操作与暂停/重置。当前只露一组变量，更多资料、自由观察、设置后置。讲解时模型最大、注释少；操作时保留对象、当前变量、验证和反馈；记录阶段显示前后证据及一句解释，再回老师讲评。
