## 2. 空间主张与品质门槛

共同视觉是“明亮的科学操作桌”：纸白背景、深蓝文字、清晰的物体轮廓、克制的钴蓝操作色。延续原计划的明亮科学游乐场方向，收敛装饰；三页共享控制语言，不共享一种卡片网格。

| 活动 | 第一眼主体 | 标志性交互 | 成功时必须看到 |
| --- | --- | --- | --- |
| 01 进化修复站 | 五节连续时间轨道，事件载体直接占据轨道 | 拿起一节，看到其他节让位；修好后沿轨道回看发展片段 | 事件按序连通，需求到技术的关系真实成立，未来说明卡可解释 |
| 02 系统维修台 | 带缺件槽位的汽车侧面几何剖面 | 装入部件后在原位置试运行，接线时能辨认方向和关系 | 能量、转动、支撑、信息在图中按功能流动 |
| 03 回波侦探 | 设备、目标、光路和距离尺构成的俯视实验场 | 改方向→发射→看回波→插入接收口，再用证据移动尺 | 单程/往返有区别，扫描增加不同证据，天气变化改变可确认信息 |

不可用“精美选择题卡 + 对错 toast”代替上述操作，不用排行榜、装饰仪表、空白大屏或长引导文字充当主体。首屏必须包含一个可以操作的具体对象；新手在未展开帮助时能找到第一步。

实施后交付门槛：

- 初次到达：可见的一句目标、一处显著操作、一处本局状态；目标建议不超过 28 个汉字，复杂规则分步出现。
- 一次确认只指出首个可修正原因，附“改哪里、怎么改”；保留所有正确部分。缺槽写“还差…”，不写“答错”。
- 每步最多一个主操作；“资料”“提示”“重开”不与主操作等权。阶段完成后原主按钮变成主动继续，不自动切走。
- 操作响应目标：普通状态变化到下一帧，视觉确认在 100ms 内出现；动画不决定领域状态，不要求等待动画才能纠错。
- 视觉评审目标：Impeccable audit ≥17/20，任何维度不得低于 3；独立 UX critique ≥34/40，系统状态、控制自由、错误恢复三项至少 3。分数是验收目标，不是当前结论。
- 无未解决 P0/P1；所有 P2 有具体处理决定。自动检测为零不能替代视觉和操作评审。

## 3. 统一视觉语法

### 3.1 配色与字体

只做课堂明亮环境的浅色方案；本期不增加主题切换。值写入新增 `.arcade-root` 的语义 token，不导入旧展厅 CSS、不改变站点 `:root`。

| token | 建议 sRGB | 角色 |
| --- | --- | --- |
| `--arcade-bg` / `--arcade-surface` | `#F5F8FC` / `#FFFFFF` | 页面与操作面 |
| `--arcade-ink` / `--arcade-muted` | `#183153` / `#4C627A` | 主文与说明，禁用不透明度制造正文层级 |
| `--arcade-primary` / `--arcade-on-primary` | `#2457D6` / `#FFFFFF` | 当前主操作、选中、可执行连接 |
| `--arcade-success` / `--arcade-success-bg` | `#087B63` / `#E8F6F0` | 已验证，配勾形和“已验证”文字 |
| `--arcade-error` / `--arcade-error-bg` | `#AD3445` / `#FFF0F1` | 待修正，配断线标记和原因 |
| `--arcade-energy` | `#F6C85F` | 能量或事件强调，只配 ink 深色文字 |
| `--arcade-control-outline` | `#6E8298` | 必须可辨认的边界，和浅色底至少 3:1 |
| `--arcade-divider` | `#D6E1EE` | 非必要分隔，不作为唯一控件边界 |

正文/按钮 `1.125rem`（默认 18px），行高 1.55–1.7；辅助说明和数据标签最小 `1rem`；任务标题 `1.5rem`；页名最大 `2rem`。界面用系统中文无衬线（PingFang SC / Microsoft YaHei / sans-serif），以 500/600/700 建立层级；测量数字使用 tabular-nums，不把等宽字体铺满页面。中文短标签不拉字距；长段落收在约 32 汉字宽内。

至少验证 ink/bg、muted/surface、white/primary、success/success-bg、error/error-bg 的 4.5:1；边界与焦点 3:1。调色必须重测这些配对，仍以实际渲染后的背景和透明度验收。

本稿已按WCAG相对亮度公式核算不透明色值：上述五组依次约12.30、6.30、6.16、4.69、5.66:1；control-outline/bg约3.71:1。它们只证明建议色值的配对，不代表尚未制作页面的实际对比或WCAG审核已经通过。

### 3.2 形状与图形

4px 基础间距，使用 4/8/12/16/24/32；组内 8–12，组间 24–32。资料容器圆角 12px，主要按钮 10px，部件轮廓根据对象形态绘制；不把所有物体画成圆角卡片。层级优先靠位置、比例、留白，至多一层柔和阴影。

SVG 几何统一 2–3 CSS px 等效描边、圆端点、明确填色；关系线有箭头、短标签；装饰线与可点击目标区分。实际功能使用可访问 DOM 控件，SVG 只承担图示与指针命中；不能让同一操作在 Tab 顺序中重复出现两次。

物体必须可辨认：电池有储能单元，电机有转轴，减速机构有啮合齿轮，轮胎接触路面，悬架连接上下支点；激光/无线电/声波通过名称、线型和图示区分，不假称现实波长比例。

### 4.1 桌面（1366×768 / 1440×900）

活动容器最大 1440px，居中；内容的高度下限由真实控件决定，不用 `transform:scale` 塞进屏幕。

│      轨道 / 剖面 / 米制场地                当前测量/结果  │  ≥360px
│                                          一次短反馈     │
├ 当前工具托盘：只显示本步需要的物体或控制器                 ┤  ≥88px
└ 可返回的上一步/取消选择                 唯一主按钮        ┘  ≥64px

768px 高首屏应同时看到目标、主体对象、工具和主按钮；额外资料在抽屉，不能靠缩小正文或挤压舞台达标。证据栏可以折叠为舞台旁的短读数；它不是常驻长说明侧栏。第一屏无营销 hero，无占位评分图。

### 4.2 平板（768–1199px）

保留完整舞台；证据栏成为舞台下方的横向短条，资料改为按钮打开的抽屉；托盘按功能分组折行。1024×768 和 768×1024 分别验收，不把手机布局简单拉宽。

### 4.3 手机（320–767px）

文档自然纵向滚动：精简页头→目标/进度→本步舞台→工具→反馈。底部只固定主操作区，预留等高底部空间和 safe-area；所有可聚焦元素可滚进可见区，不被固定栏遮住。软件键盘打开时，涉及文本的区块采用普通文档流，不锁定整页高度。

- 01 五站轨道变为竖向时间线；当前卡与落点可见，点击移动无需跨屏拖动。
- 02 只展示当前子系统的放大剖面和当前部件集合，不能把全车和 13 件缩成缩略图。
- 03 场地与测量读数分层，方向/距离用原生 range 和步进按钮；控制器在场地下方，接收口保留足够距离。
- 若空间容不下物体名称，换分区/换行；禁止隐藏关键单位、截断答案区别、强制横屏或要求捏合缩放。
- 手机不是正式比赛的额外难度档；相同档位保持同样科学容差、目标和权重。

## 5. 一套可预测的直接操作

| 输入 | 表现与规则 | 取消和恢复 |
| --- | --- | --- |
| 点击/轻触 | 选物体→点落点；选起点→终点→关系。选中物体有轮廓、名称、操作提示 | 再点选中物体或“取消选择”退出，不改变已确认答案 |
| 拖放（增强） | 鼠标移动超过 6px、触屏超过 10px 才开始；跟手副本、候选落点、占位预览；屏幕吸附范围 12 CSS px | pointercancel/lostcapture/blur/Escape 均撤销未落位预览；非法落点返回原位置 |
| 键盘 | Tab 找到物体；Enter/Space 选择，再 Tab 至目标确认；方向/标尺原生 range 左右调节并有步进按钮 | Escape 只撤销当前未提交操作/关闭抽屉，不退出整局；焦点回到来源 |
| 表单输入 | 中文输入法组合中不触发确认；昵称/理由按文本呈现 | 校验错误保留输入，消息靠近字段；不自动清空 |

44×44px 是硬下限，主要操作 48px，物体落点尽量 56px；触点间至少 8px。可见圆点可小，但命中区域不得与邻点重叠。只在独立拖柄/可拖物体使用 `touch-action:none`，页面其余区域允许滚动；不依赖 HTML 原生 drag-and-drop 完成触屏路线。

拖动阶段只有预览；pointerup 才提交一次语义动作。需要重排时保持对象身份和焦点，不能整板重建导致键盘用户丢位置。坐标从 SVG 的 inverse screen CTM 变换，考虑滚动、viewBox、浏览器缩放；屏幕吸附不改变科学判定容差。

持续选中、悬停、拖动、可落位、已落位未检查、检查正确、检查待修正、完成只读必须有不同形状/文案。按钮均具备 default/hover/focus/pressed/disabled/loading，禁用旁边说明解锁条件。状态栏只播报提交、阶段和最终结果，不能逐帧播报光点或倒计时。

## 6. 动效、纠错与注意力

| 场合 | 时长/行为 | 减少动画模式 |
| --- | --- | --- |
| 选中/落点高亮 | 100–150ms | 即时样式变化 |
| 归位/其他对象让位 | 180–240ms，transform | 即时落位，文字确认位置 |
| 单次因果试运行 | 400–700ms，可略过/重播；运行状态先提交 | 显示分步骤静态箭头与同样结论 |
| 面板/抽屉 | 180–240ms，无逐条进场 | 即时出现，焦点不变 |
| 阶段成功 | ≤600ms 局部确认，不整屏彩纸 | 勾形与可读的成果摘要 |

不用 shake 惩罚错误、不闪屏、不发恐吓碰撞音、不播放无关循环。声音默认关闭且可随时控制。光程动画明确“已放慢”，不是实时光速。反复输入中断旧动画并展示最新 snapshot；逻辑不等待 transitionend。隐藏文档停止所有动画；正式局的单调计时依旧继续，练习无时限。

帮助分两层：“怎么玩”解释控制方法，随时查看不影响首次验证分；“给我这一步的答案提示”明确提示当前 objective 将失去首次验证贡献、仍保留完成贡献。常驻帮助不用聊天气泡打断；每次仅展示一个与当前对象有关的建议。

## 7. 01：五节时间轨道 → 需求装配 → 未来说明卡

1. **时间轨道首屏**：五辆事件载体直接在五个站位上，显示年份和 ≤2 行摘要；现有 2001、2009、2015—2016、2020、2026.03 ID/事实不变，按挑战码给出相同乱序。选中卡后目标站位出现“放到这里”。重排采用插入顺移，禁止交换/插入混用。
2. **错误可定位**：“2020 在 2009 前面，先看看这两个年份”；只高亮第一对倒置，不揭示整个答案。轨道检查按钮始终可达。成功固定五站、出现可回看的顺序；一次慢速小车演示可略过，再主动“去解决需求”。此排序代表馆内历史片段，不是完整世界汽车史。
3. **三幅需求场景**：工序协作、能源转化、道路信息，每回合只显示当前场景和 2–3 个待填关系槽。技术模块放入后图中路径变化，试运行验证整条链。能源的电池/混动/氢燃料是三条可探索分支，同一 objective 一次计分，多路线并存不排名。
4. **未来说明卡**：帮助谁→需要哪种能力→仍要什么条件；三槽组成一段可读句子，和旁边的几何车形同步标记。安全、能源、无障碍、舒适四种选择均可成立，按关系一致性核验；可选理由 0–120 Unicode 字，空理由也能完成，超限保留全文并提供“不附理由”选项。
5. **结束**：展示亲手完成的轨道、三条方案关系和未来说明卡；正式分数为次级，练习只展示证据。阅读主题卡不增加新测验，不用输入字数评价观点。

## 8. 02：三张系统剖面 → 补装 → 连线试运行

1. 首屏打开动力台，只出现 4 个缺件槽及当前 4 件；guided 用轮廓暗示，standard 可有最多 2 件干扰但分批展示，不能同时铺开 13 件。提示“这里少了什么功能”，不冒充真实维修诊断。
2. 主体是几何侧面剖面：电池在地板、电机与齿轮靠车轴、车轮接触路面。点部件显示名称/功能与候选落点，放入后仍可替换未确认部件；试运行才判定。错误部件留在原槽，原因标注锚定该槽。
3. 支撑台把车身、悬架、制动、轮胎/路面分开；底盘目标必须悬架与制动同时成立，轮胎主题另观察干/湿接触；不存在单独“万能底盘块”。
4. 感知台用前向/侧后两个局部视图和信息汇聚区容纳 5 种设备；每次操作一组，信息流有明确来源。毫米波在部件、槽位、结果均标教学示意，不映射虚构 GLB 部件。
5. 装完切至同一台面的“系统关系”层；物体位置不跳变，端口浮现，按起点→终点→关系标签连接。先选端点再显示合法关系词组；边有方向、标签和可点击删除区。安装时的拖放与接线时的拖线不能共用模糊手势。
6. 连线失败聚焦一条错边，可只删它；正确边保留。动力按电能→转动→传递→接触运行；支撑按承载/缓和/减速/接触说明；感知汇入分析再给行动建议，不能画成设备直接保证安全。
7. 13 安装目标和 3 关系目标保持原 ID 与权重。全部正确确认的目标在本局锁定，可看证据；更改已确认关系需重新练习，不能撤销完成后刷首次分。

## 9. 03：发射与接收 → 扫描与尺 → 天气证据

1. **第一幕**：发射器在左，目标在右，Tx“发射口”和 Rx“接收口”同时可辨。首个动作是转方向并“发射一次”，设备与目标不被覆盖读数遮住；命中后再解锁接收挑战，首次发射不因未接线被判错。
2. **回波**：出射实线箭头、回程虚线箭头，单程 d、往返 2d 与纳秒分层展示；接错 Tx 后发射，回波到设备但没进接收器的断点在原位置可见。文案“回波到了设备，把接收头接到 Rx 接收口再试”。空接线是不完整，不扣首次资格。
3. **扫描**：方向槽采样逐步补出三种目标的轮廓；控制器位置不动，固定 -40°..40° / 4° 槽。跳过角度照样消费经过槽，重复同槽不刷证据。每目标至少两槽证据才允许确认轮廓，否则提示缺哪类观测。
4. **距离**：三条已测读数和“最近目标”选择与尺同屏；标尺 0–32m、有单位、有醒目参考点。先选目标再移动尺；错误指出实际标记与测量差，例如“标在12m，回波是8m，向设备移4m”。显示与判定共享 reflectivePoint，不能以图标边缘或大小暗示另一答案。
5. **天气**：guided 雨、standard 雾；正式不可变天气。激光/毫米波/摄像头是三条可插接证据源，两个接收位与近路障/远目标两项观察并列；“已确认”“未确认”“干扰”同时有文字和线型。未确认不等于不存在，图像不足只针对本情境。
6. **行动**：观察线 4m、路障 8m 的封闭测试道，选择继续/慢行/停下与提示灯；要求在观察线停下并提示。本局位置不是现实制动距离。错误只显示计划路径问题，不演出撞人或失败恐吓。
7. guided：角度步长 4°、光束半角 6°、尺步长 1m / ±1m；standard：2°、4°、0.5m / ±0.5m。图形吸附不改这些容差。六目标权重 150/100/150/200/200/200。

## 10. 准备、资料、结束与中断

准备页给一个可操作的无分预览和一句任务；默认突出自由练习。正式挑战设置展开后显示挑战码、档位、昵称槽位、360 秒规则和离页中断说明；验证错误旁给可执行解释，不能悄悄生成随机挑战码。教程在计时外，教程完成/跳过后仍需显式“开始练习/开始正式挑战”才启动 session，防止读教程时开始计时。

资料抽屉使用原生 dialog/等效可访问结构，进入焦点、Escape、关闭返回来源均可用；手机打开有意锁定背景滚动，关闭恢复。资料不挂载另一套游戏；辅助信息不挡住当前判断所需证据。正式计时不会因抽屉而暂停，开始前说明。

结果按“我完成了什么→本局证据→分数与条件→下一步”排列。completed/timeout/abandoned/interrupted 四态分别说明，interrupted 不显示有效比赛分；练习 score/elapsedMs 为 null，无虚构 0 分。存储失败仍可读结果，明确“本次未保存”。没有假对手、在线榜或未经验证的适龄/教学效果宣传。

沿用总计划的 700/200/100 公式、本地首局锁、挑战码、比较键及多标签保护。hidden 暂停画面但正式时钟继续；去其他 HTML/刷新/pagehide 含 BFCache 中断，返回为准备页。UI 动画、阅读、拖动次数、理由字数不参与评分。
